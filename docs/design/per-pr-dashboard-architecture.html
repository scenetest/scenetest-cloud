Per-PR Dashboard scenetest cloud

One pull request is the unit of work. The cloud SPA mounts the @scenetest/dashboard 0.13 widget directly inside a per-PR route, and that widget streams the whole PR's event log — every run — from the PR's Durable Object over a single socket, keyed on a PR-global cursor.

2 · Routing — the host owns the URL

The SPA already owns the single LocationProvider + <Router>. The PR page is just a route; the widget rides that router instead of touching history itself — so tab clicks deep-link and survive reload, and <Dashboard> stays mounted across views (stream + read model built once). 

// App.tsx — the dashboard mounts under the SPA's own optional :view? param
<Route path='/repo/:owner/:name/pr/:number/:view?' component={PrDetail} />

// PrDetail.tsx — render the bare component; it reads :view from useRoute()
<Dashboard
  transport={transport}                                  // one PR stream
  basePath={`/repo/${owner}/${name}/pr/${prNumber}`}       // router mount → tab hrefs
  apiBase={`/api/cloud/repos/${owner}/${name}/pr/${prNumber}`} // API lives elsewhere
/>

3 · What 0.13 changed here

Before — 0.11 widget

  • Shadow-root widget; mountDashboard(node, …) imperative mount via useEffect/ref.
  • Widget rewrote the host's URL with its own pushState — embedded tabs lied; reload / deep-link 404'd.
  • Transport needed a fetchState() snapshot alongside subscribe.

After — 0.13 component

  • Light-DOM Preact component (<Dashboard>), styled by the shipped stylesheet; declarative.
  • Routing rides the host's preact-iso router via {base}/:view?; basePath/apiBase split.
  • Transport is just subscribe + sendCommand — replay-on-connect covers history; fetchState() gone.

4 · Branch lineage

main carries the per-PR Durable Object log (SQLite + R2 archive) but its frontend was still the old per-run page. The per-PR backend — the id cursor, /pr-viewer-connect, prDashboardWs, and "drop /r/:runId" — lives on per-pr-dashboard (= main + that work). This branch stacks on per-pr-dashboard and adds the one missing piece: the 0.13 dashboard adoption.

The per-run viewer is now removed — the PR viewer is the only viewer. Gone: /api/runs/:runId/ws, the DO's /viewer-connect + per-run fan-out/replay (and its R2-fallback helpers); the e2e checks moved to the PR stream. Removing it surfaced a latent ordering bug — rehydrateArchived's await sat between register and replay, so a live frame on an in-flight run could jump the client's id cursor ahead of the unreplayed lower ids and drop them; rehydrate now runs before register, so register→replay is synchronous and nothing interleaves.
